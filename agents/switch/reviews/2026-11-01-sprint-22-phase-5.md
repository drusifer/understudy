## Scope and Threat Model

- **In scope / out of scope:** In: starting, replaying and stopping, the secret, the sketches allow-list, `--with` values, the cap on children, the origin and body checks. Out: the page code (Phase 6); the owner's sketches.
- **Assets worth protecting:** the right to start processes; the Jev key and its cost; input files; the secret.
- **Entry points and trust boundaries:** POST bodies from the network (untrusted until the secret is checked); sketch names, `--with` names and values, replay ids; the child process arguments.
- **Threats considered:** as the design gate, plus: output capture of the secret (SEC-008); header abuse (SEC-009); symlinks out of the sketches folder; shell injection (none: an argument list); killing other processes (only children the launcher started, by run id); a second console writing the same secret file (last one wins, documented).

## Method and Coverage

- **Reviewed by:** manual read of the diff against the design gate; an outside attack with 23 requests (every refusal on the design's list, a real start and finish, header edge cases) recorded in `UAT_PLAN_SPRINT22.md`; a test that Stop ends a real process group.
- **Tool results:** `bobp make secrets` clean; `bobp make security-scan` clean on 2026-11-01 (no dependency changed in this phase).
- **Not covered:** behavior of a sketch's own stages (owner-written); the page's use of the secret (Phase 6); a hostile process on the same machine (it could read `.understudy/dashboard.secret` only if it runs as the owner).

## Root Causes and Recommendations

SEC-008 came from assuming standard output is private; in this project it is copied into a tracked file. The smallest systemic rule: nothing secret goes to standard output or error in any command. Worth a line in `docs/SDLC.md` and a lesson (Oracle).
